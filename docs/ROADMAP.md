# Cinma — handoff and roadmap (Phases 3–7)

This is written for the next agent picking up the project. Phases 0–2 are done and accepted. Everything below is what is left, in order, with the context needed to continue without re-discovering it.

**Read first, in this order:**
1. `CLAUDE.md`: the standing brief. It is the source of truth; § numbers below refer to it.
2. `PROGRESS.md`: what exists and what was measured.
3. `docs/adr/`: decisions already made.
4. This file.

**Working rules (from the owner and the brief):**
- Work one phase at a time. At the end of each phase, report what was built, measurements against targets, and risks, in **Turkish**, then wait for confirmation.
- Commit after each step. Never push unless asked.
- New dependency → one-paragraph justification (an ADR or the phase's dependency ADR).
- Ask before data-format or engine changes. Write a short ADR for any deviation from the brief.
- Never add background processes, WebViews, telemetry, idle polling, or unbounded caches.
- Business logic lives in Rust; Swift is presentation only.

## 2. How to build, test, measure

```bash
cargo test                       # all Rust tests (incl. kill -9 suites)
cargo clippy --all-targets       # must stay clean
tools/build-core.sh Release      # Rust lib + Swift bindings (Xcode does this too)
xcodebuild -project app/Cinma.xcodeproj -scheme Cinma -configuration Release \
  -destination 'platform=macOS,arch=arm64' -derivedDataPath build/xcode build
tools/measure.sh                 # launch + idle RSS/footprint/CPU → tools/measurements.csv
tools/measure-playback.sh "ADDON_URL" movie IMDB_ID 5   # TTFF + seek, real app
```

- **Prerequisite:** `brew install mpv`. libmpv is loaded at runtime from `/opt/homebrew/lib/libmpv.2.dylib`; override with `CINMA_LIBMPV`.
- **Deployment target** lives in two places: `app/Config/Cinma.xcconfig` and `tools/build-core.sh`.

**Dev environment variables** (see `app/Cinma/DevAutomation.swift`; all are inert unless set):

| Variable | Effect |
|---|---|
| `CINMA_MEASURE=1` | print launch, TTFF and seek metrics to stderr |
| `CINMA_DATA_DIR` | use this data dir instead of the default |
| `CINMA_DEV_ADDON` | install this addon at start-up |
| `CINMA_AUTOPLAY=movie:ID` / `file:/path` | start playing automatically |
| `CINMA_AUTOSEEK=0.5,0.85` | seek to these fractions of the duration |
| `CINMA_AUTOQUIT=1` / `close` | quit, or just close the player, when done |
| `CINMA_AUTOCLOSE_AFTER=secs` | close the player after this many seconds |
| `CINMA_DEV_OPEN_URL` | handle this URL as if macOS had opened it |
| `CINMA_DEV_PEERS=127.0.0.1:6999` | extra torrent peers (loopback seeder) |
| `CINMA_MPV_LOG=v` | verbose mpv log |

**Offline torrent loop (loopback seeder + fixture addon).** Use this whenever real swarms aren't reachable:

```bash
cargo build --release -p cinma-torrent --example local_seed
target/release/examples/local_seed /path/to/video.mkv 6999 6000000   # prints INFO_HASH, upload 6 MB/s
mkdir -p /tmp/fixture/stream/movie
echo '{"id":"local.fixture","version":"0.0.1","name":"Local Fixture","resources":["stream"],"types":["movie"],"idPrefixes":["tt"],"catalogs":[]}' > /tmp/fixture/manifest.json
echo '{"streams":[{"name":"Local","infoHash":"INFO_HASH","fileIdx":0}]}' > /tmp/fixture/stream/movie/tt0000001.json
(cd /tmp/fixture && python3 -m http.server 7700 --bind 127.0.0.1)
CINMA_DEV_PEERS=127.0.0.1:6999 tools/measure-playback.sh http://127.0.0.1:7700/manifest.json movie tt0000001 5
```

Test clips (generated HDR10 4K HEVC and 1080p H.264) are in `~/Movies/cinma-corpus`. `tools/media-corpus.md` lists the real samples still needed: Dolby Vision P5/P8/P7, AV1, ASS-heavy, multi-audio, MKV with cues at the end, MP4 with moov at the end.

## 3. Pitfalls already learned (don't re-discover these)

**Agent sandbox**
- Outbound TCP from the agent's shell is proxied: closed ports look open and BitTorrent peers never connect. Test torrents over loopback (section 2).
- Real-swarm numbers must be measured by the owner, or outside the sandbox. Don't try to bypass the sandbox.

**mpv embedding**
- `vo=gpu-next` + `macvk` ignores `wid` (whether an `NSView*` or a `CAMetalLayer*`) and opens its own window. Only the OpenGL render API embeds. ADR 0004 lists the ways out.

**`CAOpenGLLayer`**
- Colorspace and `wantsExtendedDynamicRangeContent` must be set **before** the GL surface exists; changing them later is ignored.
- Swapping layers mid-playback kills mpv's vo. That is why the layer is always PQ/EDR and mpv always outputs `target-trc=pq`.
- `loadfile` must wait until the render context exists ("render-ready gating" in `PlayerViewController.start()`), otherwise mpv fails with "No render context set".
- `copyCGLContext` / `copyCGLPixelFormat` must return retained objects, and the cached ones are released in `deinit`.
- Before `render_init`: drain `glGetError` and bind FBO 0.

**Threading and teardown**
- Never call blocking mpv APIs on the main thread. Everything callable from the UI uses `mpv_command_async`.
- Teardown order: `render_free` (GL context current) → `quit` → `mpv_terminate_destroy` on the event thread.
- The host view must outlive mpv: close waits for the `Shutdown` event, with a 3 s fallback.

**Torrents**
- librqbit has no public "piece verified" hook (ADR 0009).
- Set DHT persistence explicitly; the default writes to `~/Library/Caches/com.rqbit.dht`.
- `Session::stop()` plus dropping the session brings idle CPU and sockets back to ~0.

**Memory**
- After a torrent playback, footprint stays at ~113 MB even though the live heap is ~13 MB (malloc fragmentation). `malloc_zone_pressure_relief` doesn't help.

**Strings**
- `xcodebuild` does not update `Localizable.xcstrings`. Add en + tr entries by hand; keys use `%@` / `%lld` for interpolations.

**Xcode project**
- `project.pbxproj` is hand-written. Files dropped into `app/Cinma/` are picked up automatically (synchronized folder).
- `Info.plist` is generated and merged with `app/Config/Info.plist`, which holds the URL schemes.

**Tests**
- Child-process tests: libtest prints `test name ... ` before the child's first line, so print a leading `\n` first.
- The parent must not create the DB itself; wait for the child to report "ready".

**Mouse and keyboard automation**
- Paste through the menu is blocked by the tool; use typing instead.

**Shell**
- When giving the owner commands, never use `<placeholders>`; an apostrophe inside one hangs zsh. Use plain `ADDON_URL`-style words.

## 5. Open issues to keep in mind

1. **Real-swarm TTFF and seek were never measured.** Targets: < 5 s / < 2 s, §6. Ask the owner to run `tools/measure-playback.sh` with a real addon early in Phase 3. If it misses, tune librqbit (peer limits, the stream window — `PER_STREAM_BUF_DEFAULT` is 32 MB) before adding anything else.
2. **Idle CPU after a torrent playback** is ~0.13 %; cause not identified (tokio/hyper timers suspected).
3. **Post-torrent memory** is ~113 MB. Solution paths are in PROGRESS risk 2.
4. **Playback footprint** is 470–630 MB, and rendering happens on the main thread. Move it to a dedicated GL thread (ADR 0004 CPU section).
5. **Relative seeks** (←/→) jump to keyframes (mpv default). Decide whether to use `relative+exact`.
6. **Streaming also uploads** to peers (librqbit default). Seeding policy comes in Phase 5.
7. **No streaming cache:** torrent data is deleted when playback stops. Disk policy comes in Phase 5.
8. **The queue isn't wired to Core, FFI or UI** yet; Phase 5 wires it.

## 6. Phase 3 — Browsing & stream selection (§7 Phase 3, §5.6, §5.13, §5.15)

Exit criterion: **browse → choose → play end to end through the real UI**, with launch and idle targets still met.

Suggested order:

0. **Deep-link confirmation.** In `AppDelegate.handleLink`, show an `NSAlert` (addon name and URL) before `installAddon`. Localize en + tr.

1. **Ask the owner to measure real-swarm TTFF and seek** (open issue 1).

2. **Addon protocol: catalogs, meta, search** (`crates/features/stremio`).
   - Resources `catalog` (with `extra`: `search`, `skip`, `genre`) and `meta`.
   - Partial results: streams and catalogs arrive per addon. Emit them as core events, or with an async-stream FFI pattern, so the UI fills in as addons answer.
   - Use Torrentio/Cinemeta-shaped JSON fixtures in tests (offline).

3. **Metadata: TMDB + Cinemeta fallback + ID map** (§5.13).
   - New crate `crates/features/metadata` (or inside stremio): a TMDB client using the user's key, kept in the **Keychain** (add a small Keychain wrapper — Security.framework is already linked).
   - Migration 0003: `id_map` (IMDb/TMDB/TVDB/Trakt/Simkl/MAL/AniList/Kitsu for movies, shows, episodes) and `meta_cache` (key, json, expires_at). ADR first; it is a data format.
   - Localized (Turkish) titles and overviews, logos, backdrops, cast, air dates. Cinemeta when there's no key.
   - The bundled anime ID mapping dataset can wait until Phase 6 (tracking) unless needed earlier.

4. **Library and progress** (migration 0004, profile-scoped).
   - `library_item(profile_id, meta_id, type, name, poster, added_at)`.
   - `watch_progress(profile_id, video_id, meta_id, position_s, duration_s, watched, updated_at)`.
   - Record progress from the player's `Position` events (throttled; write on pause, seek and close).
   - "Continue watching" rail. Resume position on play.

5. **Ranker** (`crates/features/ranker`, §5.6).
   - Pipeline: parse → filter → score → tier.
   - Parse `name`, `title`/`description` and `behaviorHints` (`filename`, `videoSize`, `bingeGroup`) for resolution, HDR/DV, codec, audio, size, seeders (from the Torrentio title format), release group and language.
   - Filter: CAM/TS, fakes, safety level.
   - Score against user preferences and machine capabilities. Hardware AV1 decode exists only on M3 and later; detect the chip via `sysctl hw.model` / `machdep.cpu.brand_string`.
   - Explainable: keep the score breakdown so the UI can show "why".
   - Unit-test heavily with real-world-shaped title strings.

6. **Visual design** (§5.15): dark cinema + Liquid Glass.
   - Produce mockups first (the brief says to match them).
   - Screens: Home (rotating hero, rails, Continue Watching), Title detail (backdrop, logo, seasons/episodes), Stream picker (ranked list, tier badges, "why"), Player controls (glass bar), Profile picker, Onboarding (add addons, TMDB key).
   - `NSGlassEffectView` on macOS 26 and later, `NSVisualEffectView` fallback. Respect Reduce Motion and Reduce Transparency. Hold 120 Hz.
   - Use `NSCollectionView` for grids. No SwiftUI `App` lifecycle; SwiftUI only for leaf views such as settings.

7. **Image pipeline.** ImageIO downsampling to display size, a progressive placeholder, `NSCache` with cost limits, and a **capped** disk cache. Drop caches when the window closes.

8. **Profiles.** Profile picker UI and `active_profile` switching. Core already scopes by `active_profile()`; the `profile.active` setting exists.

9. **Addon manager UI.**
   - List, enable/disable per profile (`set_addon_enabled` exists), reorder (add a repository method that updates `position`), remove.
   - "Configure" opens `{base}/configure` in the default browser via `NSWorkspace`. No WebView.

10. **Calendar** (upcoming episodes of library shows, from TMDB air dates).

11. **Trailers via yt-dlp** (§5.7).
    - Run `yt-dlp -J` as a short-lived child, then play the selected format URL directly in mpv.
    - Decide in an ADR where the yt-dlp binary comes from: Homebrew, or downloaded into app support on explicit user action. It is updated only when the user triggers it.

12. **Settings UI** (SwiftUI leaf view is fine): feature toggles (`feature_enabled` / `set_feature_enabled`), key bindings (`commands` / `set_key_binding`), TMDB key.

13. **Retire** `SliceViewController`. Keep "Open File…" as a menu command.

Exit check:
- Re-run `tools/measure.sh`: first frame < 250 ms; idle footprint ≤ 40 MB with the window open.
- The launch path must draw cached home rows from SQLite before any network (§5.16).

## 7. Phase 4 — Player complete (§5.2, §5.8, §5.9)

**Player features**
- Audio and subtitle track menus; external subtitles; dual subtitles (`secondary-sid`); audio/sub delay; chapters; speed; resume.
- **Subtitles (§5.8):**
  - query addon `subtitles` resources with `videoHash`, `videoSize` and `filename`;
  - compute the OpenSubtitles hash from the first and last 64 KB as soon as those ranges arrive (`fetch_order` already fetches head and tail first);
  - optional direct OpenSubtitles provider (credentials in Keychain);
  - language-priority auto-select;
  - **encoding detection** (Turkish `windows-1254` / `ISO-8859-9`);
  - per-file timing offset, SRT style overrides, custom fonts, SDH/forced flags; never restyle ASS unless asked.
- **Next episode (§5.9):** resolve via `bingeGroup` + series meta. At ~90 % (or the credits chapter), prefetch the next episode's meta, ranked streams, and the head/tail of the best candidate; cancel if playback stops. Auto-play countdown; skip intro/outro via chapters.
- **Seek-bar thumbnails:**
  - in-process keyframe decoder, ~160 px, LRU;
  - for streams, decode only from ranges already available — never fetch data just for thumbnails;
  - needs FFmpeg libraries: dlopen `libavformat`/`libavcodec` from the same Homebrew prefix as libmpv, or AVFoundation for local files. Write an ADR.
- **Stream switcher and auto-recovery:** on a stall or black screen, retry, then move to the next ranked stream, keeping the position.
- **Extras:** A/B loop, sleep timer, screenshot, stats overlay, shader upscaling option, HDR target-peak setting, hotkey remapping UI (the registry already supports it), `MPNowPlayingInfoCenter` + media keys, a power assertion while playing.
- **PiP:** spike only, then report feasibility before building.

**Performance (owner accepted ~19 %, but improve if cheap)**
- Render on a dedicated GL thread.
- Avoid the float framebuffer cost for SDR where possible.
- Reduce the playback footprint (demuxer cache sizes, GPU surfaces).

**Render path:** if Dolby Vision P5 samples render with wrong colours, follow the ADR 0004 solution paths (harden reparenting C, or D1 macvk `wid` patch in a custom libmpv build).

**Exit:** media-corpus checklist passes; thumbnail target < 16 ms cached / < 120 ms on demand for local files.

## 8. Phase 5 — Unified download manager (§5.3, §5.4, §5.7, §5.12)

- **Wire `cinma-queue` into Core and FFI:**
  - construct the queue lazily on the first download, or when queued rows exist at start-up;
  - forward `set_change_listener` to a core event;
  - add `downloads()`, `add_download`, `pause`, `resume` and `remove` to the FFI.
- **Engines:**
  - **Torrent download mode:** full completion, file selection in multi-file torrents, fastresume, rate limits. It stays on librqbit storage (ADR 0009); report progress through `Job`.
  - **Segmented HTTP** (`crates/features/http`):
    - dynamic segmentation (split the largest remaining segment when a connection frees up);
    - **HTTP/1.1** for multi-connection transfers;
    - per-host connection cap;
    - resume validated with `ETag` / `Last-Modified`;
    - write into a `Blob` and `checkpoint` via `Job::report_progress`;
    - when the item is played, open a segment at the read cursor: `PriorityListener` on the blob gets every read.
  - **yt-dlp jobs:** `-J` extraction, format selection, audio-only, download through the HTTP engine, mux in-process with libavformat (an ADR on how libavformat is loaded).
- **Queue UI:** `NSTableView` with diffable data sources. **Play now** for every item type: `Blob::source()` gives the player a `ByteSource`.
- **Disk policy (§5.12):**
  - "keep watched" (global and per item);
  - streaming cache quota with LRU eviction of non-kept items; never evict queued or kept items;
  - default folders per type;
  - covers both BlobStore and the librqbit download folders.
  - Replace today's "delete torrent data on stop" with this policy.
- **Seeding policy:** ratio / time / off, plus upload limits. Today librqbit uploads by default.
- **Menu bar extra in the same process:**
  - `applicationShouldTerminateAfterLastWindowClosed` → `false` once the extra exists;
  - App Nap handling via `NSProcessInfo` activities;
  - idle menu-bar-only footprint ≤ 25 MB (ADR 0003 restated target).
- **Memory:** pick up open issue 3 (post-torrent fragmentation) here, since downloads keep the session alive longer.

**Exit:** any queued item plays before it completes; kill -9 mid-download resumes correctly (extend the existing kill -9 tests to the real engines); idle targets are met with an idle queue.

## 9. Phase 6 — Integrations (each off by default; zero cost when off)

- **Casting:** Chromecast + DLNA. An in-process LAN HTTP server runs **only while a cast session is active** — the only allowed HTTP server (§1.3). AirPlay: investigate what is feasible with libmpv and report.
- **Tracking adapters (§5.14):**
  - a shared **outbox** table: a watch event writes a local record plus one outbox row per enabled adapter; a worker drains it with retry and backoff;
  - enabling an adapter later backfills history;
  - adapters: Trakt (device-code OAuth, scrobble, history, watchlist, recommendations), Simkl, AniList and MyAnimeList (via the ID map and the bundled anime mapping dataset), Letterboxd (RSS read + CSV export in its import format; no scraping);
  - tokens in Keychain, per profile.
- **Optional:** one-time Stremio account import (addon list, library).
- Each integration is a new `Feature` variant, never constructed when off.

**Exit:** each integration toggles cleanly; launch and idle footprint unchanged when off.

## 10. Phase 7 — Polish

- **Error UX:** dead streams, no peers, addon down.
- **Onboarding polish.**
- **Accessibility:** VoiceOver labels, full keyboard navigation.
- **Profile PINs:** `profile.pin_hash` exists. Use a proper KDF (or Keychain); never store plain text.
- **Backup/restore UI:** export/import the SQLite DB (use the SQLite online backup API) plus settings.
- **Packaging and signing:**
  - custom minimal libmpv build (minimal FFmpeg, libplacebo, VideoToolbox), bundled in `Contents/Frameworks` and dlopened from there first (ADR 0005);
  - this is the natural moment for render path D1 (ADR 0004);
  - hardened runtime, and notarization if the app is distributed.
- **Documented manual comparison** vs Stremio v5 / Flux / IINA with `tools/measure.sh`.

**Exit:** all §6 targets met (memory targets as restated in ADR 0003).
